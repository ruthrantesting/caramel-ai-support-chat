## Phase 6: User Story 4 - Keep Each User's Conversations Private (Priority: P1)

**Goal**: Each conversation belongs to the user who first used its identifier. Other users get `404`. Visitors who are not signed in cannot use the chat.

**Independent Test**: Two accounts. Account A sends a message with identifier X. Account B sends, continues, and clears X, and each request returns `404`. A signed-out request is refused.

### Tests for User Story 4

- [X] T071 [US4] Create `backend/src/test/java/ai/caramel/support/web/ChatEndpointsAuthTest.java`. An unauthenticated `POST /api/chat` and `DELETE /api/chat/{id}` each return `401` `UNAUTHENTICATED`. The stream does not start, and the model is not called (FR-016, Constitution VI). Depends on T021.
- [X] T072 [US4] Create `backend/src/test/java/ai/caramel/support/chat/ConversationOwnershipTest.java`. - Models and repositories before services. Services before controllers. Backend before the frontend that calls it.

## Implementation strategy

### MVP first (US1 and US2)

1. Phase 1, Phase 2.
2. Phase 3 (US1) and Phase 4 (US2).
3. Stop and check: a new visitor can sign up, send a question, reload, sign out, and sign in again. This is the spec's MVP slice (plan phase 2).

### Incremental delivery

1. US3: sessions survive reloads, and expired drafts are kept.
2. US4: conversations are private. This is the security-critical step; do not ship the chat to real users without it.
3. US5: per-user limits and brute-force delays.
4. US6: only if an email provider is chosen.
5. Phase 9 before any public deployment.
